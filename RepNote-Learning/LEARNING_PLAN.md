# Учебный маршрут

Этап — несколько уроков. С 23 октября ученик предпочитает цельные уроки:
связанные шаги одной темы до работающего поведения, с ручной проверкой.
Продвижение зависит от понимания и работающего
результата, а не от календаря. Учитель выдает по одному заданию за раз.

## Прогресс на 28 октября 2026

Пройдена базовая практическая часть 6 из 11 этапов: 0–5.
Этапы 6, 7 и 9 начаты частично; на этапе 8 выдан урок настроек темы,
этап 10 еще впереди.
Это учет изученных тем и реализованных сценариев, а не процент готовности MVP:
этапы различаются по объему, а полная приемка интерфейса еще не проведена.

«Пройден базово» означает, что основной результат реализован, код проверен
чтением и ученик сообщал о работе соответствующего сценария. Это не подтверждает
выполнение всех проверок из последнего столбца: точное соответствие макету,
крупный шрифт, доступность, утечки и расширенные сценарии остаются для приемки.
Сборки, эмулятор и тесты запускает ученик; Codex сам их не запускал.

### Что уже реализовано сверх первых этапов

- Несколько подходов на упражнение: независимый ввод, отметки, добавление,
  удаление, валидация веса/повторений и сообщения об ошибках.
- Navigation 3: список тренировок → детали → запись упражнения, передача ID,
  системный Back и стрелка возврата на деталях.
- Общий черновик тренировки: Map, неизменяемые обновления, StateFlow,
  collectAsStateWithLifecycle, разделение данных по ID шаблона и упражнения.
- Восстановление небольшого состояния через SavedStateHandle и JSON;
  ученик проверял поворот и восстановление после уничтожения фонового процесса.
- Общий счетчик выполненных подходов.
- Модели CompletedSet, CompletedExercise и WorkoutSession со снимками названий.
- Преобразования toCompletedSet, toCompletedExercise и toWorkoutSession;
  освоены map, mapNotNull,
  filterNot, sumOf, count и copy.
- Первые JUnit-проверки валидации и обновления подходов. Unit-тесты не означают
  завершение этапа 9: Compose UI tests и полноценная проверка доступности впереди.

### Текущая точка и ближайшее продолжение

Последний проверенный результат — асинхронное завершение через repository
и транзакцию Room, затем удаление черновика
и переход на результат. Ученик сообщил об успешной работе; Codex проверял
исходники, сборку не запускал. Черновик пока хранится через SavedStateHandle,
поэтому его удаление и запись Room не образуют общую транзакцию.
DAO объединяет чтение метаданных, упражнений и подходов в @Transaction;
repository собирает WorkoutSession, обратные преобразования проверены чтением.
Отдельная ViewModel результата, четыре состояния и Route подключены к чтению
из базы; старый список сессий в памяти удален. Реализация проверена чтением кода,
ученик подтвердил поворот и восстановление после завершения процесса.
История через Room Flow с открытием результата реализована; удаление с
подтверждением, ошибкой и защитой повторного запуска проверено чтением кода.
Каскадное удаление через Database Inspector и рендеринг Preview еще требуют
подтверждения ученика. Прошлый результат упражнения при вводе реализован;
также главный экран и детали получают реальные последние даты по templateId
через общую WorkoutsViewModel и Room Flow. Исходники проверены, ученик сообщил
о работе приложения; каждый сценарий запуска отдельно не подтвержден.

1. Подключить постоянное завершение через repository во ViewModel.

   Ученик подтвердил работу; Codex проверил код, сборку не запускал.

## Проверки на поздних этапах

- Последняя завершенная сессия исключает незавершенную текущую.
- Вес с запятой/точкой и пустой ввод обрабатываются корректно.
- Завершение не добавляет повторную запись при двойном нажатии.
- Редактирование шаблона сохраняет исторический снимок предыдущей тренировки.
- Черновик восстанавливается после перезапуска процесса, а не только поворота.
- UI тест: ввод подхода → отметка → завершение → запись в истории.

## Продолжение в новом чате

По просьбе ученика Codex обновляет LEARNING_LOG.md после проверки кода.
Учитель читает журнал и фактический код, сверяет
состояние проекта и продолжает следующий небольшой урок. Нельзя полагаться только
на память переписки или обещать автоматическое сохранение прогресса без записи.
